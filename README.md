# 票据夹 · 本地可搜索的发票、合同与截图资料库

> 把拍下来的发票、合同、支付截图和 PDF，变成**在你自己浏览器里**可搜索、可打标签、可按月统计的资料库。
> 纯前端 · 打开即用 · 无账号 · 无 API Key · 数据不上传 · 完全免费（无 Pro、无授权码、无条数限制）。

在线使用：<https://yguodong627-star.github.io/vibe-piaoju/>（备注：github.io 会跳转到 ysdtn.com 的对应路径）

## 谁会用、什么场景
- **主要用户**：自由职业者、小团队行政/财务助理、需要报销的上班族。
- **场景**：手机拍发票、保存微信/支付宝付款截图、收到合同 PDF——月底要按“月份、金额、对方”整理、报销、翻旧账。
- **解决的问题**：文件散在相册、微信和邮箱里，找一张发票要翻半天；在线 OCR/扫描类工具要上传隐私文件、常要注册或收费。这里全部在本机完成。

## 功能
- 拖入 / 选择 / 粘贴 图片或 PDF（可多选，手机可直接拍照）。
- **本地 OCR**：tesseract.js（简体中文 + 英文）。有文字层的 PDF 直接读文字，不走 OCR。图片自动缩放、灰度与对比度拉伸、**自动纠偏**（约 ±15° 内）。
- **规则提取**（不是模型）：金额、日期、发票号码/发票代码/单号/合同编号、买方/卖方（含甲方/乙方）、统一社会信用代码；文档类型（发票/合同/收据/截图）。
- **置信度 + 原文高亮**：每个字段显示置信度、提取依据（命中的关键字）、其他候选；点“看原文位置”会在原图上框出对应行，并在识别文本里高亮。
- **校验器**：小写金额 vs 中文大写金额是否一致；不含税金额 + 税额 = 价税合计；发票号码位数（8/20）、发票代码位数（10/12）；统一社会信用代码校验位（还会把 I/O 纠成 1/0 再校验）。不一致标红提示。
- **强制人工校对**：识别结果先放“待校对”，必须勾选“我已对照原件逐项核对”才能入库；可直接改字段、改原文并重新提取。
- 标签、类别、备注；**全文搜索**（MiniSearch + 中文二元切词，另有整串子串兜底）；按月统计（金额、份数、类别、对方排行）。
- **保留原件**；JSON 完整备份（可含原件）/导入、CSV（UTF-8 带 BOM，Excel 可开）、按月导出“原件 ZIP + 清单 CSV”。
- 数据存浏览器 IndexedDB，可申请“持久存储”。

## 使用
1. 打开网页，拖入票据。第一次识别会从本站加载约 9 MB 的识别引擎和中英文语言包（之后浏览器会缓存）。
2. 在“待校对”里点“去校对”，对照左侧原件修改字段，勾选确认后入库。
3. 在“资料库”搜索、筛选；在“按月统计”看汇总；在“备份与说明”导出。

> 本地离线使用：因为浏览器限制，`file://` 直接双击 index.html 不能加载 OCR 的 WebAssembly/Worker。请在目录里执行 `python3 -m http.server`，再访问 http://localhost:8000 。

## 实测准确性（如实记录）
测试方法：用本仓库 `tests/gen.py`、`tests/gen_holdout.py` 生成带中文文字的**合成**样本（Chrome 渲染成图/PDF，再用 PIL 做斜拍/阴影/模糊/噪点/低分辨率/盖章遮挡/扫描 PDF 退化），有标准答案；`tests/ocr-eval.js` 在无头 Chrome 里跑完整流程（含纠偏）并对比。所有样本、标准答案、识别文本与结果都在 `tests/` 里，可复跑。

**错在哪**
- 同一张发票的退化版：低分辨率（约 1/3 清晰度）、斜 6°、扫描 PDF、红章盖在金额旁都能提取到金额；**斜 12°+阴影+噪点**整体识别置信度只有 46%，金额、日期、号码全丢（工具会明确显示“未找到”，不会瞎填）。
- **红章压在日期上**，日期没识别出来；压在名称上，“有限公司”被识成“有展公司”。
- 个别生僻字/形近字会识错：如“云岫→云册”“拓→折”“拾→抢”（出现过），**这类错误置信度仍然可能显示 80% 以上**——置信度只能提示“可能错”，不能保证“没错”，所以才强制人工校对。
- 发票明细表格（有边框的单元格、红色细线）经常被识成乱码；加粗的中文大写金额偶尔整行识成乱码（此时靠小写金额，但没法用大写做交叉校验）。
- 速度（本机无头 Chrome，CPU）：约 0.5–3 秒/张，PDF 文字层 0.3 秒；引擎首次加载约 0.4 秒（本地文件）。手机会慢得多。

## 已知限制（请务必阅读）
- **这是辅助录入，不是财务凭证**。不做发票验真查验，不对接税务系统，不做汇率换算；报销、入账以原件和财务规定为准。
- OCR 对清晰的正面印刷体较好；**斜拍、阴影、小字、手写、盖章遮挡、表格线密集、反光都会明显变差**，严重时整行识错。手写体没有测试样本，**未验证，可以认为基本不可用**。
- 规则提取靠关键字与正则，版式特殊、关键字缺失、一张里有多个金额/日期时可能漏提或选错（会列出其他候选）。买卖方位置只能靠“购买方/销售方/甲方/乙方”等字样判断，甲/乙方与买卖关系不一定对应（已降低置信度并提示）。
- 只处理前 10 页 PDF；扫描 PDF 逐页 OCR，较慢。HEIC 图片部分浏览器无法解码，请先转 JPG/PNG。
- 数据只在本浏览器：清理站点数据、隐私模式、换设备、iOS Safari 长期未访问都可能丢数据。**请定期备份**。多个标签页同时操作没有冲突合并。
- 语言包使用 tesseract 的 `best_int`（体积小）版本，精度略低于完整 best 模型。

## 技术与第三方库（全部本地 vendor/，不依赖 CDN）
- tesseract.js 5.1.1 + tesseract.js-core（Apache-2.0），语言包 chi_sim / eng `4.0.0_best_int`（Apache-2.0）
- pdf.js 3.11.174（Apache-2.0）
- MiniSearch 7（MIT）
- 字体：Instrument Serif、Inter（SIL OFL 1.1）本地文件，中文回退系统宋体/苹方/微软雅黑
- ZIP 写入器、提取规则、界面均为自写
- 仓库体积约 23 MB，大头是识别引擎与语言包（约 9 MB 在首次识别时才会被下载）。
